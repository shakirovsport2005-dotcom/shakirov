# ХакКампус

Команда: **team falcodes**.

Кейс 4. «HackFlow: цифровая среда для проведения студенческих хакатонов».

Цифровая среда для студенческих хакатонов: команда сдаёт одну заявку, назначенный судья оценивает её по прозрачным критериям, организатор публикует итоги. Каждый участник получает проект в профиль и сезонные баллы.

## Локальный запуск

Нужен **Node.js 24 или новее**, дополнительных пакетов нет. На Windows полностью распакуйте ZIP в папку и дважды нажмите `start.cmd`. Браузер откроется только после проверки ответа сервера. Программа использует адрес `127.0.0.1` и сама выбирает свободный порт. Окно запуска должно оставаться открытым. Он автоматически ищет Node.js в PATH, стандартных папках установки и локальном runtime Codex. Файл запуска записан ASCII с переносами CRLF, чтобы Windows cmd корректно его читал. Для диагностики реального HTTP-подключения: `start.cmd --diagnose`. Журнал сохраняется в `data/startup.log`. `start.cmd --check` проверяет только Node.js и SQLite.

```bash
git clone https://github.com/shakirovsport2005-dotcom/shakirov.git hackcampus
cd hackcampus
npm start
```

Если получен ZIP, распакуйте его и выполните `npm start` в папке `hackcampus`. Откройте http://localhost:3000. При первом входе сервер автоматически создаст демоданные. Данные сохраняются в `data/campus.sqlite` между перезапусками. Для остановки нажмите Ctrl+C.

```bash
npm test
npm run build
node scripts/validate-artifact.mjs
```

Сборка создаёт Worker ES Module в `dist/server/index.js`. Обычному локальному запуску сборка не нужна. Настройки: `PORT` (3000), `HOST` (0.0.0.0), `DB_PATH` (путь к постоянному SQLite-файлу).

## Маршрут для жюри: заявка, оценка, +70

1. Войдите студентом `student@hackcampus.demo`. В «Моя команда» уже есть единая заявка Campus Flow. Нажмите «Сдать / обновить единую заявку», чтобы показать сдачу. Изменение заявки сбрасывает предыдущую оценку.
2. При желании войдите `new@hackcampus.demo`, укажите код **ORBITA26** и роль «Аналитик». Мария вступит в ту же команду. Один студент может состоять только в одной команде в рамках хакатона.
3. После обновления заявки войдите организатором, откройте «Проекты и заявки» и примите Campus Flow к оцениванию. Выйдите и войдите судьёй. В карточке Campus Flow раскройте «Оценить / изменить оценку». Поставьте **80, 80, 80, 80**, оставьте комментарий и сохраните.
4. Вклад критериев: 80 × 35% = 28, 80 × 30% = 24, 80 × 20% = 16, 80 × 15% = 12. Итог **80 из 100**. Другие команды уже имеют демонстрационные оценки **90, 70 и 60**. Поэтому «Орбита» займёт второе место.
5. Войдите организатором, откройте «Управление», нажмите «Закрыть приём», затем «Опубликовать итоги». Сервер не даст опубликовать результаты, пока хотя бы одна принятая заявка не оценена.
6. Войдите студентом и откройте «Мой профиль». Появятся карточка Campus Flow, роль участника, ссылка, **2 место**, **+70 баллов** и запись в истории. Такие же 70 баллов получит каждый участник «Орбиты», включая дизайнера и присоединившегося аналитика.
7. Организатор может повторить публикацию. Повторный вход студента покажет те же 70 баллов и одну запись начисления за этот хакатон.

После публикации оценки и заявки фиксируются. Для нового показа на чистых данных используйте отдельный файл базы: в PowerShell `$env:DB_PATH="data/demo-2.sqlite"; npm start`. Это не удаляет предыдущие результаты. Для полного сценария создания организатор может создать ещё один хакатон с будущим дедлайном, четырьмя весами и назначенным судьёй, а студент — свою команду и новую заявку.

## Правила

| Критерий по умолчанию | Вес |
|---|---:|
| Решение задачи | 35% |
| Реализация | 30% |
| Оригинальность | 20% |
| Качество демонстрации | 15% |

Каждый критерий оценивается от 0 до 100. Итог — сумма оценок с весами, округлённая до сотых. При создании хакатона организатор задаёт положительные веса, сумма которых равна 100. При равенстве итогов последовательно сравниваются оценки за решение задачи, реализацию, оригинальность и демонстрацию. Если все оценки одинаковы, используется ID команды. Правило нужно согласовать с регламентом пилота.

Баллы: **100 / 70 / 50** за первые три места, **10** за принятый проект вне призовой тройки. Новая или изменённая заявка ждёт проверки организатора. Организатор принимает её к оцениванию или возвращает с обязательным комментарием. Капитан может исправить её до дедлайна и повторить сдачу. Проекты на проверке или возвращённые проекты нельзя оценивать. Перед публикацией все заявки должны пройти проверку; возвращённые заявки не получают мест и баллов. У команды без заявки нет результата и баллов. Сезон определяется годом дедлайна. В профиле сумма показывается для сезона выбранного хакатона, история содержит все сезоны.

## Сервер и сохранение

JavaScript ES Modules, встроенный HTTP-сервер Node.js и встроенный `node:sqlite`. В облачном варианте Worker использует D1 через тот же интерфейс запросов. SQL-схема находится в `drizzle/0000_state.sql`, демоданные создаются кодом, а не миграцией.

Сервер проверяет роль, владение хакатоном, назначение судьи и капитана команды, дедлайн, HTTP(S)-ссылку, диапазоны оценок и сумму весов. Пользователь не задаёт себе роль через браузер. Пароли хешируются PBKDF2-SHA256 со 100 000 итераций и солью, сессии используют случайные токены, их хеши и срок 24 часа. Cookie имеет HttpOnly и SameSite=Lax, на HTTPS добавляется Secure. POST-запросы проверяют Origin, если он присутствует.

Для небольшого хакатонного прототипа все данные хранятся в одном документе SQLite. Публикация и журнал начислений записываются атомарно с оптимистической блокировкой по версии. Уникальный логический ключ начисления — `(хакатон, студент)`; повторная публикация ничего не добавляет. Конкурирующий запрос перечитывает состояние, а при исчерпании попыток получает 409. Масштабирование потребует нормализованных таблиц и SQL-ограничений уникальности.

## Проверка

Интеграционный тест вызывает реальные обработчики с SQLite: вход, создание хакатона и команды, вступление, сдача, сброс оценки, оценивание, публикация, все четыре размера наград, начисления всем участникам, отсутствие дублей, скрытие оценок до публикации, запрет чужих действий и просроченной сдачи. Дополнительный тест проверяет сохранение в файл после закрытия и повторного открытия базы.

## Развёртывание

Для Node.js-хостинга: Node 24+, команда запуска `npm start`, переменная `PORT` от хостинга, `HOST=0.0.0.0`, `DB_PATH` на **постоянном диске**. Установки пакетов и команды сборки не требуется. HTTPS должен завершаться на прокси хостинга. На таком хостинге задайте `PUBLIC_ORIGIN=https://ваш-домен`, чтобы сервер корректно проверял Origin и выставлял Secure-cookie. Проверка готовности: `/health`. У контейнера предусмотрен том `/data`.

```bash
docker compose up --build -d
```

Облачная версия опубликована через Sites. Worker использует базу D1 с привязкой DB и SQL-миграцию из drizzle. Файлы README и презентации доступны на /README.md и /presentation.

## Пилот и развитие

Один вуз, два последовательных хакатона. Сравнить время от закрытия приёма до публикации с предыдущим ручным процессом, долю команд с принятым проектом от всех зарегистрированных команд и долю участников первого события, вернувшихся на второе. Целевые значения задаются как гипотезы, а не как достигнутые результаты.

Дальше: поиск участника по навыкам, очередь к менторам, публичная ссылка на портфолио только по желанию студента. Перед реальным вузовским пилотом нужны восстановление доступа, университетский SSO, ограничение попыток входа, аудит действий и резервные копии. Общие тестовые аккаунты предназначены для демо.

## Дополнительные функции

- Самостоятельная регистрация студента по имени, почте и паролю от 10 символов. Роль назначает сервер, получить права судьи или организатора через регистрацию нельзя.
- До пяти участников в команде. Выход до дедлайна и закрытия приёма. Капитан команды с другими участниками не может покинуть её.
- Проверка заявок организатором, возврат с причиной, повторная сдача и сброс устаревшей оценки.
- Общий рейтинг сезона по опубликованным результатам. При равном количестве баллов участники делят место.
- Фотографические ИИ-иллюстрации на входе и в шапке хакатона, встроенные в страницу. Это не фотографии реального вуза. Исходники и WebP находятся в `assets/`.

Техническая конфигурация находится в `config/deployment.json`. Скрытая папка конфигурации из выдаваемого проекта удалена. Для запуска используется обычный Node.js, данные остаются в SQLite.
